## 1. 総合所見および技術的実現性マトリクス

本報告書は、Leaf（現アクアプラス）の古典的ビジュアルノベル『雫～しずく～』（1996年発売、LVNS エンジン）のデータ構造解析および現代 macOS 向けネイティブ再実装に関する初期調査成果を総括したものです。

過去のオープンソース実装（XLVNS、MGLVNS、lfview、akkera 氏の sizuku ツール群、GBALVNS）のコード監査および製品版実物ディスクのバイナリ照合を通じ、**本エンジンのデータ構造は極めて論理的かつ自律しており、現代プラットフォーム上での完全なネイティブ再実装が十分に実現可能であることを実証しました**。

| サブシステム | 対象原版リソース | 解析成果と突破点 | 現代 macOS ネイティブ実装方式 |
|---|---|---|---|
| **アーカイブコンテナ** | `MAX_DATA.PAK` | 11 バイト加算ローリング XOR 復号；ファイル名テーブル差分解析 | `ShizukuCore` 純 Swift ストリーム展開・検証器 |
| **音声コンテナ** | `bgmfile.PAK`, `soundds.PAK` | LAC フォーマット解析；BGM マッピング式および OST 音響照合 | `AVAudioEngine` + `AVAudioPlayerNode` ハードウェア混音 |
| **画像デコーダ** | `*.LFG` (LEAFCODE) | 16色 4bit パレットのニブル複製展開；縦列優先ビットインターリーブ | Metal テクスチャパイプライン + CPU/Compute 展開 |
| **スクリプト仮想マシン** | `SCN*.DAT` (全 197 本) | SCN 2段 LZS3 反転フラグ伸張；外層 Block と内層マクロの分離 | コルーチン駆動二層仮想マシン（Event VM + Inline VM） |
| **フォント組版** | `KNJ_ALL.KNJ` | 24×24 1bpp 垂直 3 ストリップ走査配置；葉文字コード直接参照 | 1,852 字テクスチャアトラス + 3 パス硬影文字描画 |

## 2. LVNS エンジンアーキテクチャ全景

『雫』『痕』『To Heart』は、初期 Leaf ビジュアルノベルシリーズ（LVNS: Leaf Visual Novel System, 1996–1999）の技術的共通基盤の上に構築されています。

```text
                     ┌────────────────────────┐
                     │ Windows 95 Sizuku.exe  │
                     └───────────┬────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
 ┌─────────────┐          ┌─────────────┐          ┌─────────────┐
 │ MAX_DATA    │          │ bgmfile.PAK │          │ soundds.PAK │
 │ (LEAFPACK)  │          │ (LAC / Ogg) │          │ (LAC / WAV) │
 └──────┬──────┘          └─────────────┘          └─────────────┘
        │
   ┌────┴───────────────────────────┬──────────────────────┐
   ▼                                ▼                      ▼
197 SCN Scripts               195 LFG Images         1 KNJ Font
(Bytecode & Dialogue)         (16-color CGs/BGs)     (24x24 1bpp Bitmap)
```

1. **実行モデル**：起動時に `MAX_DATA.PAK` の目録を展開し、シナリオ進行に応じて `SCN%03d.DAT` バイトコードブロックを逐次ロード。
2. **イベントとメッセージの分離**：SCN 内部は物理的に「イベントセクション」と「メッセージセクション」に二分され、外層ステートマシンと内層インライン演出器が協調動作。
3. **描画合成**：基準解像度は 640×400。立ち絵と背景は独立してロードされ、16 色インデックスパレットを介してリアルタイム合成。

## 3. バイナリ資産の検証結果

### 3.1 LEAFPACK 復号アルゴリズム
`MAX_DATA.PAK`（5,756,792 バイト）は独自の LEAFPACK 構造を採用。先頭 8 バイトのマジック `"LEAFPACK"` に続き、uint16 リトルエンディアンで総ファイル数（`0x0193` = 403 ファイル）が記録されています。

データ領域およびディレクトリテーブルは 11 バイトの加算ローリング鍵で難読化されています：
$$\text{StoredByte} = (\text{PlainByte} + \text{Key}[k \bmod 11]) \bmod 256$$
ディレクトリ領域の 24 バイト項目末尾に存在する空白パディングの統計的性質を利用することで、EXE を逆アセンブルすることなく暗号鍵 `71 48 6a 55 9f 13 58 f7 d1 7c 3e`（ASCII `qHjU…`）を完全復元しました。403 本の全ファイルが無損失で抽出可能です。

### 3.2 LFG 画像復元（LEAFCODE）
195 枚の `*.LFG` 画像は 16 色 4bit パレットを保持：
- **ニブル展開**：4bit 各色成分は `(nibble << 4) | nibble` により標準の 8bit RGB 値に拡張。
- **垂直インターリーブ走査**：`direction == 0`（縦列モード）では、2 列単位の縦ストリップとして走査されるため、標準的な行優先 RGBA バッファへ並び替えを実行。

### 3.3 SCN バイトコード伸張
全 197 本のスクリプト（`SCN000.DAT` 〜 `SCN196.DAT`）は反転フラグ LZS3（リングバッファ `0x1011`）で圧縮されています。ヘッダに記載された展開後サイズで厳密にストリームを切断することで、過去ツールに見られた末尾ゴミデータの混入を防止します。

## 4. 現代的アーキテクチャ設計

### 4.1 エミュレータ／Wine 方式の排除
初期検討における互換レイヤー検証の結果、以下の問題が確認されました：
1. **音声遅延とループ乱れ**：レガシー DirectSound は互換層下でクロック同期ズレやループ時のノイズが発生。
2. **描画品質の劣化**：Metal による整数倍 Crisp スケーリングや 60Hz ProMotion ディスプレイ同期を活かせない。
3. **macOS HIG への不適合**：標準メニューバー、トラックパッドジェスチャー、構造化 JSON セーブデータなどの近代化機能を提供できない。

これらを踏まえ、**クリーンルームによる Swift + Metal ネイティブ再実装**を決定しました。

---

## 5. 結論

本調査により、『雫』の製品版 Windows 95 データは完全に可読であり、暗号解読上の障害が存在しないことが実証されました。これにより、デジタル保存および現代プラットフォームにおける高品位なネイティブ復元に向けた確固たる基盤が整いました。
