## 1. マイルストーン全景

本プロジェクトはアジャイル開発手法を採用し、バイナリ解析からネイティブ GUI 実装に至るまで、6 つの明確な工程段階に分割して推進されました：

| マイルストーン | 開発担当領域 | 主な成果物および検証項目 | 検証状況 |
|---|---|---|---|
| **第1段階 (M1)** | 基礎データ復号と形式検証 | PAK 内 403 ファイル抽出完了、24×24 フォント出力、LFG 画像展開 | ✅ **受入完了** |
| **第2段階 (M2)** | SCN 逆アセンブルと VM 基盤 | 197 本のスクリプト逆アセンブル出力、外層 Block 遷移、13 種 Skip 命令 | ✅ **受入完了** |
| **第3段階 (M3)** | ネイティブ音響系と混音処理 | Ogg BGM 25 曲ループ再生、WAV 効果音 13 本混音、CoreAudio リサンプリング | ✅ **受入完了** |
| **第4段階 (M4)** | Metal 描画と高忠実度復元 | 25×13 サウンドノベル文字組、3 パス影文字、13 種トランジション、隠し音楽室 | ✅ **受入完了 (Ver.1.0)** |
| **第5段階 (M5)** | 中国語化解析・フォント再構築 | 2014 翻訳パッチ復号 (199 SCN)、4,726 字 24×24 フォント、単調 DP 写像 (2,872 字)、ビート分割、15 頁後記復元 | ✅ **受入完了 (Ver.1.2)** |
| **第6段階 (M6)** | PC-98 OPNA FM 音源と製品収束 | PC-9801/9821 OPNA FM 24 曲実機録音、二重音源構成、決定的回帰検証 (113/113)、13 終結全網羅、二重 DMG 配布 | ✅ **正式リリース (Ver.1.5)** |

## 2. 詳細マイルストーン仕様および受入基準

### 第1段階：暗号解読とフォント組版パイプライン (M1)
- **M1.1: 独自 PAK コンテナの復号と整合性検証**
  - 11 バイト加算循環鍵アルゴリズムを実装し、`MAX_DATA.PAK` 内全 403 ファイルを抽出。
  - **受入基準**：403 ファイルすべてのハッシュ整合性を確認。ディレクトリ名に文字化けがないこと。
- **M1.2: KNJ 24×24 ビットマップフォントデコード**
  - `KNJ_ALL.KNJ`（133,344 バイト）内の 1,852 字を 3 垂直走査ストリップから復元。
  - **受入基準**：`preview/knj_atlas.png` を出力し、文字の欠損がなく、1-based 配列参照が正確であること。

### 第2段階：二層仮想マシンとスクリプト制御 (M2)
- **M2.1: SCN スクリプト伸張と境界切断処理**
  - 反転フラグ LZS3 伸張処理を実装し、ヘッダ記載の展開後サイズで厳密に切断。
  - **受入基準**：全 197 本のスクリプト末尾にゴミ文字の混入が一切生じないこと。
- **M2.2: イベント仮想マシン（Event VM）と Skip 命令処理**
  - 外層ストリームに存在する 13 個のダミー Skip オペコードを特定し、プログラムカウンタを安全に進める。
  - **受入基準**：`SCN001.DAT` から `SCN002.DAT` へのブロックジャンプがデッドロックなく滑らかに遷移すること。

### 第3段階：ネイティブ音響サブシステムの統合 (M3)
- **M3.1: LAC コンテナとオーディオグラフ構築**
  - `AVAudioEngine` による遅延ゼロの再生グラフを構築。25 曲の BGM ループ再生と 13 本の効果音混音を実現。
  - **受入基準**：BGM 移行時やフェードアウト時にポップノイズや音割れが発生しないこと。
- **M3.2: 11,025Hz モノラル音源による CoreAudio 例外クラッシュの根治**
  - `AVAudioConverter` を統合し、モノラル 11,025Hz 音声を 44,100Hz ステレオ Float32 へ動的リサンプリング。
  - **受入基準**：`P01-P13` 効果音の連続トリガー時にも `NSException` が一切発生しないこと。

### 第4段階：描画パイプラインと忠実度復元 (M4)
- **M4.1: サウンドノベル行組版と影文字描画**
  - 25 列 × 13 行の等幅グリッド、字間 1px、行间 6px、および 3 パス硬影文字重ね描きを再現。
  - **受入基準**：テキストボックスの半透明合成が Windows 95 原版とピクセル単位で一致すること。
- **M4.2: 13 種トランジションと螺回転換（GURUGURU）幾何アルゴリズム**
  - `(27, 12)` を中心とする 16px タイルブロックの外向き螺旋描画アルゴリズムを復元。
  - **受入基準**：40×25 タイルが欠落なく外向きに画面全体へ螺旋展開すること。
- **M4.3: 隠し音楽室の逆アセンブル解明と復元**
  - タイトル画面 `(448, 128)` の時計塔右上窓に対する不可視判定および `0x408d40` メインループを再現。
  - **受入基準**：`VIS17.LFG` 画面上でオルゴール調の音楽室 UI が起動し、ESC/マウス右クリックで正常に復帰できること。

### 第5段階：中国語化逆アセンブル・フォント再構築・劇本整合 (M5)
- **M5.1: 2014 有志翻訳パッチの復号とアンパック**
  - 4 バイト XOR 循環暗号で秘匿された 2014 年有志翻訳補正ファイル `data.bin` を解析し、199 本の SCN 劇本ストリーム（3,834 行の翻訳文）を完全抽出。
  - **受入基準**：199 SCN の抽出整合性を検証し、全テキスト行を正確に抽出できること。
- **M5.2: 4,726 スロット 24×24 中国語ビットマップフォントの抽出と再構築**
  - 翻訳パッチ DLL より拡張フォントデータを抽出し、4,726 文字スロットの二値化フォントバイナリ `cnfont_4726.bin`（340,272 バイト）を構築。
  - **受入基準**：ビットマップ抽出の欠損や歪みがなく、原版同等の視認性を達成すること。
- **M5.3: 単調動的計画法（DP）による文字コードマッピングテーブル再構築**
  - Shift-JIS / Leaf 文字コードと GBK との非互換性を解決するため、単調増加最小編集距離 DP アルゴリズムを設計し、2,872 字の写像表 `cn_code2char.json` を生成。
  - **受入基準**：劇本内の全文字参照におけるヒット率 100%、未知文字・文字化けゼロを達成すること。
- **M5.4: 劇本ビートスライス（Beat Slice）動的進行パイプライン**
  - 日本語原文と中国語訳文の文字長差に起因する待機ビート（Wait Beat）の音声・演出不整合を解消。`cnSlices` と `cnCommitted` による動的配分を導入し、原版打鍵リズムに同期したテキスト展開を実現。
  - **受入基準**：効果音や画面切り替えとの同期が崩れず、文字の飛びや取りこぼしが生じないこと。
- **M5.5: 文末記号吸着処理と空ビートの自動透過**
  - 鍵括弧・感嘆符・疑問符等の行頭ぶら下がりを防ぐ吸着アルゴリズムを導入し、訳文割り当てが 0 文字となった空ビートを自動スキップ。
  - **受入基準**：不自然な改行や空送りによる進行停止が一切生じないこと。
- **M5.6: ラテン文字コードテーブルのオフセット補正**
  - 翻訳フォント内のラテン文字スロット 7 箇所のオフセットずれ（`a`〜`g`）を補正し、外来語や人名英表記の乱れを解消。
  - **受入基準**：英字混じりテキストの描画が 100% 正確であること。
- **M5.7: 2014 翻訳班 15 頁あとがきの復元とクロスセーブ防護**
  - 翻訳チームが追加した 15 ページに及ぶあとがきシナリオ（`SCN095` -> `SCN233` -> `SCN234`）を復元。さらに `SaveError.missingScenario` および `hasBlock` 判定を実装し、日中異言語版間のセーブデータ読み込みクラッシュを完全防止。
  - **受入基準**：あとがき画面のページ送りおよび専用 UI が滑らかに機能し、異版セーブの相互互換ロードが安全に行われること。

### 第6段階：PC-98 OPNA FM 原生音源・工程収束・Ver.1.5 リリース (M6)
- **M6.1: PC-9801/9821 OPNA (YM2608) FM 原生音源のビットパーフェクト実機録音**
  - PC-98 実機環境からプロ仕様機器を用いて 1996 年 PC-9801 原版の全 24 曲 OPNA FM 音源（44.1kHz / 16-bit / 43.3MB）を高忠実度に内部収録。6 音 FM + 3 音 SSG + 1 音 ADPCM の重厚なレトロサウンドを完全再現。
  - **受入基準**：24 音軌のノイズフロアが -84dBFS 以下であり、実機音色と完全に合致すること。
- **M6.2: 二重音源ミキシングアーキテクチャと動的ホット切替**
  - `AudioController` に二重オーディオバックエンド（`bgmSource`: 0=Win95 CD-DA Ogg, 1=PC-98 OPNA FM）を実装し、ゲームプレイ中に設定メニューからシームレスに音源を即時切替可能に。
  - **受入基準**：音源切替時のポップノイズがなく、音量・再生位置が滑らかに引き継がれること。
- **M6.3: FM ループポイント高精度調律とワンショット保護**
  - スペクトル波形解析によりループ楽曲の境界時刻（`MUS11` 8.75 秒、`MUS16` 9.00 秒等）を厳密指定し、ジングルや終幕用ワンショット 6 曲を単発再生で保護。
  - **受入基準**：ループ継ぎ目での位相ズレや音飛びがなく、ワンショット曲が終了後に適切に消音すること。
- **M6.4: 選択肢グリッドレイアウトの原版準拠復元**
  - フローティング中央配置を廃止し、原版の 25×13 テキストグリッド座標系に復帰。物理行間隔 `choiceRowGap = 1` ルールを適用。
  - **受入基準**：選択肢の視覚的配置が 1996 年 Windows 95 および PC-98 原版と 100% 一致すること。
- **M6.5: 決定論的スナップショット回帰テストフレームワーク**
  - `SaveClock` による物理タイムスタンプの凍結と固定乱数シードを導入し、`/tmp/shizuku_shot_saves/` 配下の全 113 個のテストセーブに対する完全自動回帰検証系を構築。
  - **受入基準**：113/113 個のセーブデータ復元・状態ハッシュが 100% 一致すること。
- **M6.6: 全 13 種エンディング自動到達パス回帰**
  - `EndingPathTests.swift` を作成し、全 13 種類のエンディング到達ルート（全滅・真相・逃亡等）を全探索回帰。
  - **受入基準**：全 13 エンディングへの到達中にデッドロックや未処理分岐が皆無であること。
- **M6.7: Meta-Save（大域進行度）の独立永続化**
  - GBA SRAM `0x10` 構造に着想を得て、4 個の周回横断フラグ（`0x00, 0x01, 0x45, 0x46`）を `meta_save.dat` へ独立分離。
  - **受入基準**：個別セーブスロットを削除した場合でも、タイトル画面のクリア特典やエンディング到達フラグが恒久保持されること。
- **M6.8: ネイティブ SwiftUI About ウィンドウ**
  - macOS ガイドラインに準拠した独立 About ウィンドウを実装。開発史・クレジット・オープンソース謝辞を掲載し、Dark/Light モードに対応。
  - **受入基準**：Command+W による高速終了をサポートし、滑らかに応答すること。
- **M6.9: タイプライター風逐字描画と適正速度早送り**
  - 30ms 逐字描画（垂直同期 2 フレームに 1 文字反転）を再現し、読みやすさを保つ適正早送り（17/60 秒、約 59.1 文字/秒）を実装。
  - **受入基準**：文字の描画欠損がなく、早送り解除時に瞬時に該当文字で停止すること。
- **M6.10: macOS App Nap 対策と描画クロック固定化**
  - `latencyCritical` トークンによるアクティビティ管理を適用し、バックグラウンド移行時のクロックダウンを防止。
  - **受入基準**：常時 60.0 FPS で安定動作し、CPU 負荷が 3.5% 未満を維持すること。
- **M6.11: Ver.1.5 二重 DMG 配布パッケージの生成と暗号化納品**
  - 日本語原版（`Shizuku_Restored_Ver.1.5.dmg`）および簡体中国語完全版（`Shizuku_Restored_CHS_Ver.1.5.dmg`）を自動生成し、189MB の暗号化パッケージを構築。
  - **受入基準**：Apple Silicon および Intel Mac（macOS 14/15/26）上でドラッグ＆ドロップにより即座に単独起動すること。
